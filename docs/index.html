Gate reference — what each one exists to catch

hadolint

1 · the Dockerfile itself

Container as root (DL3002), unpinned base image (DL3007), unpinned apt packages (DL3008). Runs in parallel with the build, so a bad Dockerfile fails in seconds instead of after a two-minute image build.

sast — Bandit

2 · code you wrote

Insecure patterns in your own source: shell=True, eval, unsafe deserialisation. A library scanner cannot see these — the flaw is in a line you typed. Caught B602 (command injection) in this repo.

sca — pip-audit

3 · dependencies you consume

Known CVEs in third-party packages. Your code can be flawless and this still fires. Caught 74 vulnerabilities across 8 packages from requests==2.19.1 / flask==2.0.1.

gitleaks

4 · secrets you committed

API keys, tokens and passwords in the tree. Nothing else here covers this — SAST reads code patterns, SCA reads versions, Trivy reads packages, and a committed AWS key passes all three. Demonstrably blocked a release; see the evidence below.

image-scan — Trivy

5 · the artifact you ship

OS packages, language packages and base-image tooling — the layer the other two cannot see. Failure is limited to fixable findings (ignore-unfixed), so the gate stays meaningful instead of permanently red.

deploy

not a gate — the thing being gated

Publishes to GHCR, and declares all five gates in needs:. GitHub will not start it if any of them failed. The security control is the job graph itself, not a report anyone reads afterwards.
